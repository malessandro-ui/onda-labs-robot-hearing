# Onda v0.17: native object-bound unified hearing acceptance

## Scope

Two *additive* harnesses exercise existing Onda public APIs:

1. MuJoCo: actual `phone` mocap body and `robot_head` poses -> `PoseTimeline` -> object-bound `AcousticSceneRenderer` -> independent spatial and semantic rings -> `UnifiedHearing` policy vector.
2. NVIDIA Isaac Lab: actual `RigidObject` scene primitives `/World/envs/env_0/OndaV017Phone` and `/World/envs/env_0/OndaV017Head` -> native RigidObject root poses -> identical Onda pipeline. Both named USD prims are verified to exist.

This package does NOT modify `src/onda_hearing`, PyTorch, BEATs, Isaac Lab, MuJoCo, or your existing regression suite. It requires the previously applied v0.17 BEATs `extract_features()` adapter correction.

## Engineering boundaries

- Direct path analytically rendered audio is not sound generated by PhysX or MuJoCo and not physically calibrated occlusion, diffraction or room acoustics.
- Position truth comes only from simulator API into the **evaluator**; the robot-facing policy vector receives acoustic observations, not a true phone coordinate or emitter identity.
- The optional `--expected-label` gate allows a reproducible known-label assertion. Without it, the semantic gate checks that real model inference produced valid class scores, **not** that a particular class was predicted.
- Semantic predictions describe the **whole analysis window** and are **not assigned to a specific localized source**. With one sounding source, spatial/semantic outcomes can be evaluated together, but this is not a general multi-source association algorithm.
- Simulated capture timestamps are derived from integer PCM sample indices. Neither capture age nor simulator time can be treated as physical wall-clock capture-to-publication latency.
- `min_score=0` in the acceptance brain is intentional: demonstrates finite class scores even when confidence is low. It is **not** a recognition-quality accuracy threshold.
- The synthetic validation waveform includes broadband energy for time-delay localization. It is not a natural telephone ring. Do not use its semantic output as a recognition benchmark.
- The native validation code has not been executed on a running Isaac Lab / MuJoCo installation by its author. Its results must be evaluated on Shadeform; failures should be reported, not bypassed.

## Test A: MuJoCo unified moving phone

```bash
cd /ephemeral/onda-nvidia/onda-v015
PYTHONPATH="$PWD/src:$PWD/tools${PYTHONPATH:+:$PYTHONPATH}" \
python tools/validate_v017_mujoco_unified.py \
  --wav /tmp/onda_v017_hybrid_ring.wav \
  --checkpoint "$ONDA_BEATS_CHECKPOINT" \
  --labels "$ONDA_BEATS_LABELS" \
  --beats-dir "$ONDA_BEATS_MODULE_DIR" \
  --device cuda --duration-s 8 \
  --out docs/validation/v017_native/mujoco_unified.json
python -m json.tool docs/validation/v017_native/mujoco_unified.json
```

Optional known-label check: append `--expected-label "Dial tone" --min-label-score .15` (recommended only if the test recording has that known event).

**PASS** requires >= 10 distinct valid spatial decisions, valid semantic inference, angular error P75 <= 15° (controlled one-source validation waveform), 0 PCM discontinuities, 0 pose misses, 0 ring-overrun recoveries, no worker errors, and P99 nonblocking policy reads <= 10 ms. Inspect wall duration separately; the test is paced to allow the BEATs worker to run.

## Test B: native Isaac Lab USD scene object

```bash
cd /ephemeral/onda-nvidia/onda-v015
export ONDA_V017_TEST_WAV=/tmp/onda_v017_hybrid_ring.wav
bash tools/run_v017_native_isaac.sh
python -m json.tool docs/validation/v017_native/isaaclab_unified.json
```

The harness creates two kinematic `RigidObject` scene objects, checks their USD prims, moves the source object and rotates the microphone rig during a genuine Isaac Lab `Isaac-Cartpole-v0` physics run. It records physics-sourced world-space poses and renders into Onda v0.16 + Onda Sound Brain. It preserves the task policy observation and produces the same checks as MuJoCo.

Isaac Lab is launched via `/ephemeral/onda-nvidia/IsaacLab/isaaclab.sh -p` and, on the tested machine, a finite hard process exit avoids the known Kit `close()` stall. This is **not** a pattern for production robot runtime.
